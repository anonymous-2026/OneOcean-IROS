Platform Guide

Inspect and reuse the OneOcean environment product.

OneOcean is organized around a reusable ocean-environment product. The same grounded data contract supports the quantitative benchmark, the scene-backed underwater backend, and a static browser demo that can be hosted on GitHub Pages.

Overview

How this page maps to the paper workflow

The paper evaluates methods on tasks grounded in a shared ocean data product. This page keeps that structure explicit: acquire or rebuild the environment product, export the right footprint, then reuse that footprint across quantitative and scene-backed evaluation.

01

Acquire or regenerate

Start from the released dataset or rebuild a custom crop from Copernicus Marine currents and GEBCO bathymetry.

02

Export the right footprint

Choose tiny, scene, or public variants depending on whether the target is debugging, browser preview, task deployment, or public release.

03

Drive tasks consistently

Use the same grounded currents in both backends so tables, videos, screenshots, and manifests all trace back to one environment contract.

Resolution

Supported data footprints

OneOcean does not expose one fixed precision. Effective resolution depends on the chosen region, the requested time span, the depth levels, and which export variant is generated from the pipeline.

Current released or generated examples

Artifact Time Depth Lat × Lon Step
Main local example30 daily steps26 levels240 × 240~0.00418°
Public variant357 daily steps26 levels41 × 410.25°
Tiny variant357 daily steps1 level62 × 101~0.01°
Web subset13 sampled dates4 sampled levels21 × 210.50°

The browser subset is intentionally downsampled for fast static deployment and does not represent the maximum supported data fidelity.

How to interpret precision

  • Space: current examples span from ~0.25° broad coverage down to ~0.00418° for tighter local crops.
  • Time: artifacts range from a focused 30-day crop to a year-scale public release with 357 daily steps.
  • Depth: current generated products span from a single shallow layer in tiny to 26 levels in broader examples.
  • Pipeline: these are concrete released footprints, not hard limits. Different region, time, and depth requests can be regenerated when upstream coverage exists.

Pipeline

Regenerate or tailor the environment product

The pipeline aligns currents, bathymetry, optional tides, and masks into one canonical environment file, then exports variants for benchmarking, scene deployment, and lightweight web delivery.

01

Ocean fields

Copernicus Marine variables such as currents, SSH, salinity, and temperature.

02

Bathymetry

GEBCO GeoTIFF crops provide terrain structure and masking for the requested region.

03

Merge and align

Data_pipeline/run_pipeline.py interpolates, aligns, merges, and writes the environment product.

04

Export and reuse

Produce combined_environment.nc, variants, drift exports, and scene-facing task assets.

Customize region, time, and depth

Use geographic bounds plus start/end timestamps to define the slice. Depth can be passed as a range or as an explicit list.

python Data_pipeline/run_pipeline.py --overwrite \
  --lat-min 32.0 --lat-max 33.0 --lon-min -66.5 --lon-max -65.5 \
  --start 2024-06-01T00:00:00 --end 2024-06-30T00:00:00 \
  --depths "0,10,20,50,100,200" \
  --include-tides

If tides are surface-only, the pipeline applies a configurable depth-decay profile. This is an engineering approximation, not a full 3D tidal model.

Export variants for different uses

Variants are written under Data_pipeline/Data/Combined/variants/ with a consistent schema and manifest.

python Data_pipeline/generate_variants.py \
  --which tiny,scene,public \
  --overwrite
  • tiny: fast debugging and small browser-safe exports
  • scene: main scene grounding footprint for task deployment
  • public: broader temporal coverage with lighter spatial resolution
Credentials: Copernicus Marine access uses COPERNICUSMARINE_USERNAME and COPERNICUSMARINE_PASSWORD. GEBCO GeoTIFF files must already exist under Data_pipeline/Data/.

Execution

Two backend modes, one environment grounding

The core benchmark backend is optimized for scale, tables, and reproducible run manifests. The OceanGym scene backend is optimized for underwater scene semantics, screenshots, GIFs, and qualitative task evidence. Both consume currents derived from the same environment product.

Core benchmark backend (benchmark_core)

Export a drift cache from combined_environment.nc, then run task matrices with shared metrics and reproducible manifests.

python -m benchmark_core.cli.export_drift_cache \
  --nc Data_pipeline/Data/Combined/variants/scene/combined/combined_environment.nc \
  --u-var utotal --v-var vtotal --time-index 0 --depth-index 0 \
  --out runs/benchmark_core/_cache/drift_scene_t0_d0.npz

python -m benchmark_core.cli.run_matrix \
  --drift-npz runs/benchmark_core/_cache/drift_scene_t0_d0.npz \
  --preset paper_v1 \
  --dynamics-model 6dof \
  --constraint-mode hard \
  --bathy-mode hard \
  --validate

OceanGym scene backend (tracks/oceangym_benchmark)

Export a time series of grounded currents and inject them into the scene task suite for qualitative deployment evidence and task videos.

python tracks/oceangym_benchmark/export_current_series_npz.py \
  --dataset Data_pipeline/Data/Combined/combined_environment.nc \
  --out_npz runs/_cache/data_grounding/currents/cmems_center_uovo.npz

python tracks/oceangym_benchmark/run_task_suite.py \
  --preset ocean_worlds_camera \
  --episodes 3 \
  --current_npz runs/_cache/data_grounding/currents/cmems_center_uovo.npz

This backend assumes a working HoloOcean client plus packaged worlds installed locally.

Use benchmark_core when

you need broad method comparisons, reproducible tables, difficulty sweeps, and larger run matrices.

Use oceangym_benchmark when

you need scene semantics, screenshots, GIFs, MP4s, and qualitative validation inside packaged environments.

Reuse

Publish artifacts others can rerun

The practical public bundle is small and explicit: a released environment footprint, its manifest, representative run manifests, and the media proving that the scene backend really consumed the same grounding.

Recommended artifact bundle

  • combined_environment.nc or the specific exported variant used in the study
  • variants/<tier>/variant.json with the exact footprint
  • runs/benchmark_core/**/results_manifest.json
  • runs/oceangym_benchmark/**/media/ screenshots, GIFs, and MP4s
