Workflow

How this page maps to the paper workflow

OneOcean is not just a simulator. The core artifact is an ocean-environment product that can be regenerated, subsetted, exported, and reused across multiple task backends with shared provenance.

03

Reuse the same environment grounding in the quantitative benchmark and the underwater-scene backend so metrics, media, and provenance stay aligned.

Quickstart

From dataset artifact to first run

All commands below assume the repository root as the working directory. Start from the released dataset unless you need a new region or time window.

Use the released dataset

Download a prebuilt combined_environment.nc and place it under Data_pipeline/Data/Combined/ to avoid refetching upstream data.

Zenodo · Hugging Face

Run a first benchmark task

Export a drift cache from the dataset, then run a canonical navigation task in the fast quantitative backend. 

python -m benchmark_core.cli.export_drift_cache \
  --nc Data_pipeline/Data/Combined/combined_environment.nc \
  --u-var utotal --v-var vtotal --time-index 0 --depth-index 0 \
  --out runs/benchmark_core/_cache/drift_t0_d0.npz

python -m benchmark_core.cli.run \
  --drift-npz runs/benchmark_core/_cache/drift_t0_d0.npz \
  --task go_to_goal_current \
  --controller go_to_goal \
  --difficulty medium \
  --n-agents 1 \
  --episodes 10 \
  --seed 0 \
  --out-dir runs/benchmark_core/quickstart

If tides are not present in the dataset, replace utotal/vtotal with uo/vo.

Folder contract: the pipeline writes into Data_pipeline/Data/, and the released dataset mirrors that layout so the benchmark and scene-backed tools can run without path changes.

Resolution

What resolution the data product supports

There is no single fixed “OneOcean resolution.” The pipeline accepts custom region, time, and depth requests; the effective precision is bounded by the chosen crop, variant export, and the upstream ocean-data sources used to assemble the environment product.

Current shipped/generated footprints

Artifact Time Depth Lat × Lon Horizontal step
Main local environment example 30 daily steps 26 levels 240 × 240 ~0.00418°
Public release variant 357 daily steps 26 levels 41 × 41 0.25°
Tiny release variant 357 daily steps 1 level 62 × 101 ~0.01°
GitHub Pages explorer subset 13 sampled dates 4 sampled levels 21 × 21 0.50° after web downsampling

The explorer subset is derived from the public release and intentionally downsampled for browser delivery; it is a visualization asset, not the maximum-fidelity dataset.

How to interpret “supported precision”

Space Current examples span from ~0.25° public coverage down to ~0.00418° for a tighter local crop used to build the main environment product.
Time Current released/generated artifacts range from 30 daily steps for a focused month-long crop to 357 daily steps for broader yearly coverage.
Depth Current artifacts span from a single shallow layer in the tiny variant to 26 depth levels in the main/public products.
Pipeline The pipeline is not hard-coded to these exact footprints: you can regenerate different region, time, and depth configurations as long as the upstream data are available.

Pipeline

Regenerate or tailor the environment product

The pipeline aligns bathymetry, currents, optional tides, and masks into a canonical environment file, then exports smaller variants for debugging, scenes, the web, and broader public release.

Ocean fields
CMEMS / GOPAF variables such as salinity, temperature, currents, SSH, and optional tides.
Bathymetry
GEBCO GeoTIFF crops provide terrain structure and masking for the chosen region.
Merge and align
Data_pipeline/run_pipeline.py aligns, interpolates, merges, and compresses the environment product.
Export and reuse
Produce combined_environment.nc, variants, drift exports, and scene-facing assets for downstream tasks.

Customize region, time, and depth

Use geographic bounds plus start/end timestamps to define the slice. Depth can be expressed as a range or an explicit list. 

python Data_pipeline/run_pipeline.py --overwrite \
  --lat-min 32.0 --lat-max 33.0 --lon-min -66.5 --lon-max -65.5 \
  --start 2024-06-01T00:00:00 --end 2024-06-30T00:00:00 \
  --depths "0,10,20,50,100,200" \
  --include-tides

If tides are surface-only, the pipeline applies a configurable decay profile along depth. This is an engineering approximation, not a full 3D tidal model.

Export variants for different uses

Variants are written under Data_pipeline/Data/Combined/variants/. Each one carries a variant.json manifest so downstream media and tables stay auditable. 

python Data_pipeline/generate_variants.py \
  --which tiny,scene,public \
  --overwrite
tinyfast iteration, smoke checks, small web exports
scenemain scene and task grounding footprint
publicbroader temporal coverage with lighter spatial resolution

Credentials: CMEMS access uses COPERNICUSMARINE_USERNAME and COPERNICUSMARINE_PASSWORD. GEBCO GeoTIFF tiles must already exist under Data_pipeline/Data/.

Execution

Two backend modes, one environment grounding

The benchmark core backend is optimized for scale and paper tables. The OceanGym scene backend is optimized for underwater scene semantics, media, and qualitative deployment evidence. Both consume currents derived from the same environment product.

Core benchmark backend (benchmark_core)

Export a drift cache (.npz) from combined_environment.nc, then run task matrices with shared metrics and reproducible manifests. 

python -m benchmark_core.cli.export_drift_cache \
  --nc Data_pipeline/Data/Combined/variants/scene/combined/combined_environment.nc \
  --u-var utotal --v-var vtotal --time-index 0 --depth-index 0 \
  --out runs/benchmark_core/_cache/drift_scene_t0_d0.npz

python -m benchmark_core.cli.run_matrix \
  --drift-npz runs/benchmark_core/_cache/drift_scene_t0_d0.npz \
  --preset paper_v1 \
  --dynamics-model 6dof \
  --constraint-mode hard \
  --bathy-mode hard \
  --validate

OceanGym scene backend (tracks/oceangym_benchmark)

Export a time series of data-grounded currents and inject them into the scene task suite for qualitative deployment evidence and task videos. 

python tracks/oceangym_benchmark/export_current_series_npz.py \
  --dataset Data_pipeline/Data/Combined/combined_environment.nc \
  --out_npz runs/_cache/data_grounding/currents/cmems_center_uovo.npz

python tracks/oceangym_benchmark/run_task_suite.py \
  --preset ocean_worlds_camera \
  --episodes 3 \
  --current_npz runs/_cache/data_grounding/currents/cmems_center_uovo.npz

This backend assumes a working HoloOcean client plus packaged worlds installed locally.

Use benchmark_core when
you need broad method comparisons, reproducible tables, difficulty sweeps, and large run matrices.
Use oceangym_benchmark when
you need scene semantics, underwater screenshots, GIFs, MP4s, and qualitative validation inside packaged environments.

Reuse

Publish artifacts people can actually rerun

The safest public bundle is a small set of aligned artifacts: the dataset footprint, its variant manifest, the run manifests, and representative media generated from scene-backed tasks.

Recommended artifact bundle

  • combined_environment.nc or the exported variant used for the study
  • variants/<tier>/variant.json with the exact footprint
  • runs/benchmark_core/**/results_manifest.json
  • runs/oceangym_benchmark/**/media/ screenshots, GIFs, and MP4s

Deploy the website on GitHub Pages

This repository serves the public website from docs/. The explorer on this page uses a compact static subset, so it remains deployable without server-side infrastructure.
